## Open risks / known issues

- Dependency advisories: dev-only `braces` (high, via `eslint-config-next`) and `esbuild` (moderate, via `drizzle-kit`); 4 moderate in `drizzle-kit` remain with `--omit=dev` because better-auth depends on it (esbuild dev-server issue, not reachable at runtime).
- CSP uses `'unsafe-inline'`.
- TypeScript is 6.0.3, not the latest 7 (ADR 0002).
- RustFS instead of MinIO; image is unpinned (`latest`); not exercised yet (ADR 0003).
- `next start` prints a warning with `output: standalone` (E2E uses `next start`; the container uses the standalone server). Harmless but untidy.
- Local dev defaults `minioadmin` / `dopamean` credentials exist in compose and E2E config for local use only; production must set real values.
- The local dev database contains one test row inserted into `audit_event` while checking the trigger; it cannot be deleted by design. Recreate the volume (`docker compose down -v`) for a clean dev DB. Nothing in tests or seed depends on it.
- Better Auth CLI was not usable; auth schema is hand-written (ADR 0002 item 3).
